# 适配器层

`src/core/` 是纯逻辑，本目录负责把它翻译成某个具体运行时能吃的东西。
**核心不依赖适配器，适配器单向依赖核心。** 加新运行时 = 加一个目录，核心不动。

## 规划中的适配器

### `nodegraph/`（主线）
把核心逻辑通过 [genshin-ts](https://github.com/josStorer/genshin-ts) 编译成千星沙箱节点图。
注意 genshin-ts 的节点图作用域约束（详见 `docs/02-editor-boundary.md`）：

- `number` 是浮点，`bigint` 是整数；取模/位运算必须用 `bigint`
- 列表索引用 `bigint` 时要包 `idx(...)`
- 列表/字典必须同质；空数组用 `list('int', [])` 显式声明类型
- `dict(...)` 只读 —— 词典正好适配；**可变状态（棋盘/手牌/分数）必须用节点图变量**
- 不支持递归 / async / Promise；`while(true)` 有循环上限
- `Object.*` / `JSON.*` 在节点图作用域基本不可用 —— 挪到顶层编译期
- **顶层作用域是编译期**，可以读文件、用 npm 库、预计算 ← 词典分桶靠这条

因此移植 `src/core` 时的改写清单：
| core 里的写法 | 节点图里要改成 |
|---|---|
| `Array.map/filter` 链式 | 视支持情况保留，或展开为显式循环 |
| 对象字面量 `{r,c,ch}` | 结构体（编辑器里先定义）或平行数组 |
| `Set` / `Map` | 节点图字典变量 |
| 递归 | 显式栈 + 循环 |
| 浮点下标 | `idx(bigint)` |

### `html-ui/`（配合 Ayaya_Miliastra_Editor）
`tools/gen-board-html.mjs` 已经能产出 15×15 棋盘。
Ayaya 工具支持「HTML 作为 UI 源码并导出为 .gil」，用它避免手摆 225 个格子。

### `client-script/`（原 `lua/`）—— 7.1 起可能可用，但**先别建目录**

**状态（2026-09-20）**：7.1（9-23 上线）官方预告「界面编辑新增一类可挂载客户端脚本的控件」。
多位创作者的创体服视频提及 Lua，官方称呼是「客户端脚本」。**官方完整 API 文档尚未放出。**
详见 `docs/01-research.md` 的核查记录与 `docs/00-decisions.md` 的 ADR-005。

**为什么现在不建目录**：没有 API 文档时写的适配器必然要重写。
等 `docs/03-verify-in-editor.md` 的 P0-0 跑完，拿到真实接口再动手。

**现在能做、且不会白做的准备**：
1. 核心可移植性 —— **已完成**，由 `npm run portcheck` 机器强制
2. 熟悉 Lua 基础：table、函数、闭包、模块思路、错误处理（不要押注任何 Lua 框架）
3. 服务端/客户端职责切分 —— 已在 ADR-004 / ADR-006 定好，见下节

**核心 → Lua 的移植清单**（`npm run portcheck` 会统计各类出现次数）：

| JS 写法 | Lua 对应 | 注意 |
|---|---|---|
| `Array.map/filter/reduce/find` | 手写 `for` 循环 | 当前核心约 20 处 |
| `Set` / `Map` | table 当集合/字典用 | 当前约 6 处 |
| 模板字符串 `` `${x}` `` | `..` 拼接 | 当前 2 处 |
| `??` / `?.` | 显式 `if`/`and or` | 当前 1 处 |
| 0 基下标 | **Lua 是 1 基** | `rcToIdx/idxToRc` 要整体 +1，是最易错的一处 |
| `null` | `nil` | 空格子判断要一并改 |

**⚠️ 拿到正式 API 前不要大量用 AI 生成脚本代码** —— 会生成看似合理但不存在的接口。
先手写最小示例摸清真实接口，再把接口文档和可运行示例当作上下文喂给 AI。

## 服务端 / 客户端切分（重要）

拼词游戏必须遵守：

- **服务端**：词典校验、计分、回合推进、牌堆 —— 一切裁决。
  客户端能伪造消息，词典校验放客户端等于送分。
- **客户端**：选中高亮、拖拽预览、动画 —— 纯表现。

7.1 的客户端脚本能力**恰好开在不能放裁决的那一侧**，所以它只应承担表现层：

| 模块 | 端 | 落地方式 |
|---|---|---|
| 格子高亮、拖拽预览、落子动画、UI 补间 | 客户端 | 客户端脚本（Lua?） |
| 棋盘与手牌栏渲染、控件生成 | 客户端 | 同上 |
| **词典校验** | **服务端** | 节点图 + 分桶词典 |
| **计分、回合推进、牌堆** | **服务端** | 节点图 |

凡"这个词合不合法、得几分"一律发信号回服务端判定。
**推论**：分桶词典的工作完全不受脚本能力影响 —— 它本来就注定在服务端。
