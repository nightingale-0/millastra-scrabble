## 编辑器核心机制

- 编辑器名「千星沙箱」，可视化节点图（蓝图式），**仅支持 PC 端**
  - 推荐配置：Win10/11 64bit、16GB 内存、SSD、RTX 3060 级独显、DirectX 11
- 连线分执行流（顺序）与运算流（数据）
- 节点分类：功能 / 事件（只有出口）/ 分支循环 / 纯运算
- 支持**结构体**和**字典**，社区已有专门解析这两类变量的工具库
- 两种编辑模式：
  - **超限模式**：功能开放（自定义技能、阵营设定），只能用奇偶游玩
  - **经典模式**：可用提瓦特角色，**关卡最高 4 人**，有部分角色专用节点
- 关卡设置里可配「人数设置：关卡游玩人数设置、分组设置」
- 有「多人试玩」模块，支持模拟延迟

## 硬性约束

| 约束 | 数值 | 出处 |
|---|---|---|
| 单张节点图节点上限 | **~3000** | genshin-ts TODO 明确列出 "Auto-detect node graph limit overflow (3000)" |
| 其它编辑项上限 | 见官方指南「编辑项范围限制」专章 | 需进游戏查 |
| 高频 tick 逻辑 | 社区实测会导致高峰期服务器报错 | 知乎讨论 |

**性能红线**：社区用「全局计时器 + 0.03s 循环定时器」模拟 tick，实测在 8–12 点高峰期会让地图出错。
本项目严禁任何高频轮询，一切事件驱动。genshin-ts 里 `setInterval <= 100ms` 会直接触发性能警告。

## 全量界面控件清单

交互按钮、文本框、图片、弹窗、图文输入框、进度条、计时器、计分板、**卡牌选择器**、
悬浮交互页、状态显示区、**消息队列**、界面动效、全屏界面动效、自定义按钮、自定义开关、
自定义小地图、特殊数字控件。
组织工具：界面控件组管理、素材库、界面布局。

**对本项目直接可用的三个现成件：**
- **卡牌选择器** —— 决策弹窗 / 选项卡片 / 超时事件，天然适合"选字"或"确认/质疑"
- **计分板** —— 自定义变量排名，直接就是 2–4 人分数栏
- **消息队列** —— 支持结构体推送，适合"XX 拼出 XXX，得 N 分"的战报流

## 关于脚本能力 —— 已更正（2026-09-20 第二次核查）

### 官方口径（已独立证实）

7.1 前瞻直播总结（bwiki）千星奇域部分逐字写着：

> - 界面编辑新增一类**可挂载客户端脚本的控件**

同时可确认：7.1 于 2026-09-23 上线；官方综合指南的更新日志**最新条目仍是 7.0（2026-08-12）**，
即 7.1 的完整脚本文档尚未放出。存在官方 7.1 奇匠指引长图公告（日文镜像见 KUSO GAME
https://www.kusogame.com/124643/ ），但正文为图片，无法抓取文字。

### Lua（很可能为真，但本人未能独立证实）

第三方分析（GPT-6 经屏幕录制核查官方长图与 B 站创作者视频，2026-09-17）称：

- 官方长图的功能路径为：「界面控件管理」中新增「**客户端控件容器**」→ 容器内创建编辑客户端控件
  → 通过客户端脚本动态控制控件，改善 UI 交互、实现动画效果、制作更复杂的 **2D 玩法**
- **多位创作者的 7.1 创体服视频明确提及 Lua**，而官方预告用的称呼是「客户端脚本」
- 点名的创作者与视频：戀祈（7.1 Lua / UI 补间动画 / 2D 玩法及协作模式，约 9 分半，9-16 发布）、
  小猪之最Thepig（《千星奇域终于能写代码了？！》）、小问号Official（《你将能在原神玩到这么多 2D 游戏》）、
  砂塘学徒（《我在千星奇域还原了 Windows 操作系统》）
- 协作模式为**按资产拆分**：把存档内的实体、玩家模板、职业、实体节点图等拆到不同协作部分

**我的核查结果**：上述官方部分（客户端脚本控件、协作模式、7.1 日期、指南仍停在 7.0）
与我独立查到的完全吻合。但 **Lua 一词、「客户端控件容器」术语、协作模式的资产拆分细节，
我都没能独立证实** —— 那批视频 9/16–17 发布，搜索引擎尚未索引；B 站搜索页 robots 禁止直连；
HoYoLAB / Fandom 抓取失败；act.mihoyo.com robots 禁止；容器 shell 出网被允许列表拦截。

**当前应采取的立场**：按「客户端脚本能力即将开放，具体语言很可能是 Lua」来准备，
但**不要把任何具体 API 写进既定技术方案**，等 9-23 后进游戏实测。

### 对本项目最关键的一条推论

客户端脚本开在**客户端**。拼词游戏的词典校验与计分**必须服务端权威**，否则玩家可伪造合法单词。
所以即使 Lua 为真，切分仍是：

| 模块 | 端 | 归属 |
|---|---|---|
| 格子高亮、拖拽预览、落子动画、UI 补间 | 客户端 | Lua / 客户端脚本 |
| 棋盘与手牌栏渲染 | 客户端 | 同上 |
| **词典校验** | **服务端** | 节点图（分桶词典的工作不白做） |
| **计分、回合推进、牌堆** | **服务端** | 节点图 |

**好消息**：Lua 省掉的正是原方案里最没把握的 UI 那半边（见 docs/03 的 P0-1）。
若脚本能在运行时创建与定位控件，15×15 = 225 格就是一个双层循环，P0-1 直接消解。

- **[script-1024/genshin-miliastra-file-format](https://github.com/script-1024/genshin-miliastra-file-format)** ——
  `.gip`(Project) / `.gil`(Level) / `.gia`(Asset) / `.gir`(Runtime)，Protobuf 序列化，
  头部标记 `0x0326`、尾部 `0x0679` 被严格校验。

  → 2D UI 布局本身是结构化数据，理论上可程序化生成（但 GIL 逆向仍标注"进行中"）
