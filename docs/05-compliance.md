# 合规风险分档 —— 动任何第三方工具链之前必读

## 事实

千星奇域官方明确「严厉打击采用外挂、第三方工具等违规行为」。2025-11-07 发布的违规处理说明中，
公布的违规行为包括「任何使用外挂、脚本等第三方软件，**非正常获取、修改游戏数据**的账号」，
处罚含警告与账号封停，**首批封禁名单中最高封禁 50 年**。

这条界线官方没有给出逐条细则，所以下面是我的风险判断，不是官方表态。**最终由你自己决定。**

## 风险梯度

| 档位 | 做法 | 判断依据 |
|---|---|---|
| 🟢 **相对低** | 在本地生成 `.gia` 资产文件，再通过游戏内官方的**「资产导入导出」**功能手动导入 | 走的是官方公开通道，产物是合法格式文件。本仓库 `tools/` 下的所有脚本都属于这一档 —— 它们只生成文件，不碰游戏进程 |
| 🟡 **中** | 直接覆写本地 `.gil` 存档（Ayaya 的 .gil 导出、genshin-ts 的 `inject`） | 属于修改本地游戏数据文件。是否被判定为"非正常修改游戏数据"，官方没有明确表态 |
| 🔴 **高** | 视觉识别 / OCR / 模拟点击自动操作游戏客户端 | Ayaya 作者自己的免责声明就写着"若使用任何向游戏客户端直接操作的自动化功能，使用者需自行评估合规风险并承担相应后果"；Wu-Yijun 仓库直接写"使用视觉方案的模拟自动化工具暂不列举" |

## 本项目的建议立场

**走 🟢 档。** 理由：单人项目，且大概率想正式发布关卡吃创作者激励。多花的手动导入时间，
远低于账号被封的代价。

**本仓库的设计已经为此留好了余地**：
- `tools/` 下所有脚本**只读写本目录内的文件**，不访问游戏目录、不启动游戏进程、不发网络请求
- `dist/board.html` 可以直接用浏览器打开做设计验证 —— 这一步零风险
- 分桶词典产物是纯 JSON，怎么进游戏由你决定

## 如果你选择 🟡 档

至少做到：
- [ ] **动手前手动备份存档**（genshin-ts 的 inject 会自动备份，但别只依赖它）
- [ ] 在**专门新建的废弃测试存档**上先跑通，不要碰正式工程
- [ ] genshin-ts 的注入安全规则本身是一层保护：目标节点图必须为空、或名字以 `_GSTS` 开头，
      否则拒绝注入。**不要为了图省事去设 `skipSafeCheck = true`**
- [ ] `.gitignore` 已经把 `*.gil *.gia *.gip *.gir` 和 `backup/` 排除在版本库外 —— 别把存档提交上去

## 绝对不要做

- 视觉自动化 / 模拟点击（🔴）
- 任何形式的账号交易（官方明确列为违规行为）
- 把本仓库产物包装成"外挂"分发
