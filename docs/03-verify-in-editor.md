## P0-0　客户端脚本到底是什么　【7.1 已于 9-23 上线，这条现在排第一】

**为什么排第一**：如果脚本能在运行时创建和定位控件，下面的 P0-1 直接消解 —— 225 格变成一个双层循环。
这一条的答案会重排后面所有优先级。

**先确认基本事实**：
- [ ] 「界面控件管理」里有没有**「客户端控件容器」**这个东西？实际叫什么名字？
- [ ] 写脚本的语言是不是 **Lua**？（官方称呼是"客户端脚本"，创作者视频称 Lua，以游戏内为准）
- [ ] 编辑入口在哪？编辑器内置编辑框，还是能用外部编辑器？

**然后是决定架构的五问**（这五条不搞清楚，写出来的代码大概率要返工）：

| 待确认 | 为什么影响决策 | 对本项目的具体含义 |
|---|---|---|
| Lua 版本、标准库、`require` 与模块组织 | 决定现成代码/库能否复用 | `src/core` 能否近乎直译过去 |
| 脚本能访问哪些实体、变量、节点图接口 | 决定 UI 能否与关卡玩法连通 | 格子点击如何把意图传给服务端 |
| **客户端↔服务端通信能力** | 决定多人共享状态怎么做 | **最关键**：落子意图上报 + 裁决结果下发 |
| 本地文件导入导出、外部编辑器支持 | 决定能否建立 Git / 代码审查 / AI 编码流程 | 决定本仓库能否直接对接，还是只能手抄 |
| 调试器、日志、热重载、性能限制 | 决定迭代成本 | 225 个控件各挂脚本会不会炸 |

**最小验证项目**（建议就做这个，别一上来做全棋盘）：
做一个 **3×3 迷你棋盘**，跑通这条链路：
1. 脚本生成 9 个格子控件（验证：能否循环生成、能否定位）
2. 点击格子 → 高亮（验证：事件响应、状态、调试方法）
3. 点击"确认" → 把 9 格内容发给服务端节点图（验证：客户端→服务端通信）
4. 服务端查一个写死的 3 词词典 → 结果回传 → UI 显示对/错（验证：服务端→客户端回传）
5. 拉第二个人进来（验证：分清"每人独立的 UI 状态"与"共享的棋局状态"）

跑通这 5 步，整个项目的技术风险就基本清零了。跑不通第 3、4 步，就说明客户端脚本还不能承载本项目，
退回纯节点图方案。

**⚠️ 不要做的事**：在拿到正式 API 文档之前，不要大量用 AI 生成脚本代码 ——
会生成看似合理但根本不存在的接口。先手写最小示例，把真实接口摸清楚。

## P0-1　UI 能否批量生成网格？

**为什么关键**：15×15 = 225 格。如果只能手摆，2D UI 方案的工时会超过 3D 方案，整个路线要推翻。

> **7.1 更新后先跳到 P0-0。** 若客户端脚本能在运行时创建并定位控件，本条直接作废 ——
> 225 格就是一个双层循环。只有在脚本做不到时，才需要往下验手摆/阵列工具。

**怎么验**：
1. 新建一个空关卡，进千星沙箱 → 界面控件
2. 试着做一个 5×5 的按钮网格，记录：**手工摆 25 个格子花了多久**
3. 检查有没有这些能力：
   - [ ] 「界面控件组」能否整组复制粘贴？一次能复制几个？
   - [ ] 有没有阵列/网格批量生成工具？（官方指南提到「编辑工具」里有**网格阵列、环形阵列、批量创建副本**，确认它对 UI 控件是否也生效，还是只对 3D 实体生效）
   - [ ] 控件位置能否用节点图在运行时设置？（如果能，就可以摆 1 个模板 + 运行时生成 224 个）

**结论分支**：
- 能批量生成 → 走 2D UI，继续 P0-2
- 只能手摆但 25 格 < 10 分钟 → 225 格约 1.5 小时，可接受，仍走 2D UI
- 只能手摆且很慢 → 改用 **Ayaya 的 HTML→.gil 路线**（见 P1-1），或缩小棋盘到 11×11

## P0-2　控件是否支持拖拽？

**为什么关键**：Scrabble 的手感核心是"拖牌到格子"。

**怎么验**：放一个交互按钮，看它的事件列表里除了"点击"还有没有按下/拖动/释放。

**结论分支**：
- 支持拖拽 → 按经典手感做
- 只支持点击 → 改成**两段式点选**（先点手牌选中 → 再点目标格落下）。
  这条完全可行，很多手机版拼词游戏就是这么做的，但要在原型阶段验一下手感是否别扭。

## P0-3　玩家能否自由打字输入？

**为什么关键**：决定英文版是否可行。中文版用点选更自然，英文版如果不能打字，就只能靠拖牌。

**怎么验**：查「图文输入框控件」和「特殊数字控件」的实际能力：
- [ ] 图文输入框是**玩家可编辑**，还是只是创作者预设的图文混排展示？
- [ ] 有没有任何控件能接收玩家的键盘文本输入并把字符串传给节点图？

**注意**：官方还有个「自定义外显文本」功能（Lv.2 解锁），那是**创作者预设文案**，不是玩家输入，别搞混。

---

## P0-4　棋盘状态存哪儿？

**为什么关键**：225 格 × 每格（字母 + 分值 + 加成 + 归属）不是小数据。

**怎么验**：
- [ ] 节点图变量能否存 225 长度的列表？有没有长度上限？
- [ ] 「结构体」能否作为列表元素？（即 `List<Struct>` 是否支持）
- [ ] 「字典」的容量上限是多少？
- [ ] 「局内存档」（Lv.4 解锁）能存多大？能否存整个棋盘用于断线重连？

**退路**：如果 `List<Struct>` 不支持，改用 4 个平行的基础类型列表（字母列表、分值列表…），
核心代码里 `board.mjs` 的 `rcToIdx/idxToRc` 就是为这种扁平化准备的。
