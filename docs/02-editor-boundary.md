# 编辑器边界：什么必须手工做，什么能用代码做

> 来源：genshin-ts 官方模板的 `docs/EDITOR_BOUNDARIES_ZH.md`。
> 这是社区最成熟的工具链作者总结的边界，直接采信。

## 必须在编辑器里完成（代码碰不到）

- 场景与地图：地形、出生点、复苏点、导航、实体摆放、布局、装饰
- **节点图容器**：目标 NodeGraph 必须先在地图中创建并保存，注入器才能识别它的 id
- 元件 / 元件组 / 资产：建筑、敌人、掉落物、特效、**UI 资源**、音频、图标
- 组件挂载与基础配置（运行时不能动态增删组件）
- **界面布局、界面控件组、交互按钮、计时器控件、计分板控件** ← 本项目的 UI 全在这条里
- 千星沙箱中的**信号定义**
- 全局计时器管理器中的全局计时器定义（普通定时器可在节点图里直接建）
- 商店模板、货币定义、背包模板
- 能力单元、战斗预设（本项目用不到）
- 文本气泡、小地图标识、音效播放器、铭牌

## 适合用代码做

- 游戏阶段与状态切换 ← `src/core/game.mjs`
- 经济计算、奖励、计分 ← `src/core/score.mjs`
- 运行时创建元件、移除实体、触发结算
- **UI 显隐切换、控件组激活、按钮事件响应** ← UI 的"行为"归代码，"长相"归编辑器
- 信号收发与多实体协作

## 对本项目的直接含义

**棋盘的"样子"必须在编辑器里摆出来（或用 Ayaya 的 HTML→.gil 生成），
但棋盘的"行为"全部由代码驱动。**

所以工作切分是：

| 部分 | 归属 | 本仓库对应 |
|---|---|---|
| 225 个格子控件的存在与位置 | 编辑器 | `tools/gen-board-html.mjs` 辅助 |
| 格子的点击响应、高亮、填字 | 代码 | 适配器层（待写） |
| 手牌栏 7 个槽位的存在 | 编辑器 | 同上 |
| 发牌、补牌、洗牌 | 代码 | `src/core/tiles.mjs` |
| 计分板控件 | 编辑器 | — |
| 分数怎么算 | 代码 | `src/core/score.mjs` |
| 词典数据 | 代码（编译期预计算） | `tools/build-dict.mjs` |
| 词典校验时机与结果处理 | 代码 | `src/core/game.mjs` |
| 信号定义（客户端→服务端上报意图） | **编辑器先定义**，代码按名引用 | 适配器层 |

## 一条容易踩的坑

> `createPrefab` / `createPrefabGroup` 是在运行时**创生已经做好的元件资源**，
> 不是动态创建新的编辑器资产。

也就是说，不存在"用代码凭空造一个新控件类型"这回事。能复用的前提是**先在编辑器里做好模板**。
这正是 `docs/03-verify-in-editor.md` 的 P0-1 要验的核心问题。
